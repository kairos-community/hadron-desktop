# isotope boot splash

Installed as `/usr/bin/kairos-splash`. kairos-init keeps an existing binary at
that path instead of linking its stock `kairos splash` there, and runs it in
both halves of the boot:

- **initramfs**: kairos-init's `50kairos-splash` dracut module copies it (and
  its libraries) into the initramfs. It runs with no arguments until SIGTERM at
  switch-root.
- **booted system**: `kairos-splash.service` runs it with `--duration=3s`
  before the login screen. A drop-in in
  `rootfs/usr/lib/systemd/system/kairos-splash.service.d/` orders it before
  `ly@tty1`.

`kairos.splash=0` on the kernel command line turns it off for one boot.

## The animation

"One light": the core of the Isotope mark is the only light on the screen.
It lights first, the hexagon shell takes the light on its inner faces, then
the sixth side lifts off and two soft shafts of light leave past its ends.
Under the mark the isotope wordmark (Urbanist SemiBold) fades in, with the
Kairos credit at the foot. While a disk passphrase is asked the side stays
seated, and the light gets out once the disk is open. The mark is the brand
yellow of `theme/palette.toml` (`brand`, `brand_glow`, `brand_deep`), which
never follows the desktop theme.

`--render=FILE.ppm --at=SECONDS [--size=WxH]` draws one frame without a
framebuffer; `make test` checks that a settled frame shows the mark.
`--slot=0|1|2 --progress=0..1 --digest=... --version=...` preview the row of
the three system images, which is not wired to the boot yet and is not drawn
without them. `--bare` draws the scene alone, the ground the GRUB background
and the lock screen share.

## Renderers

- **Framebuffer** (the normal case): draws into `/dev/fb0`, which every DRM
  driver exposes through fbdev emulation (simpledrm from the first moment of
  the initramfs, then virtio-gpu, i915, amdgpu...). The VT is switched to
  graphics mode so fbcon does not draw over it, and back on exit. The
  background is `tools/gen-grub-bg.py`'s gradient, so GRUB, the splash and the
  login screen read as one. When a native driver replaces simpledrm mid-boot,
  the splash notices the new geometry and reopens the framebuffer.
- **Text**: the VGA-16 console animation, for a VT with no framebuffer. It
  shows the wordmark only: the console cannot draw the mark's triangles.
- **No terminal**: prints `ISOTOPE <version>` and exits.

The version comes from `/etc/kairos/branding/splash/version`, which the
Dockerfile writes before kairos-init builds the initramfs, so both halves show
the same release.

Nothing can shape a font this early in boot, so the splash carries its text
as pixels: `masks.h`, generated by `tools/gen-splash-masks.py` from the
installer's fonts (the wordmark in Urbanist, text in Inter and JetBrains
Mono, three sizes each for the screen sizes the layout scales to).

## Disk passphrase

In the initramfs the splash is also a systemd password agent
(`agent.c`, systemd's `docs/PASSWORD_AGENTS.md`). When something asks for a
password with `systemd-ask-password` (the `isotope-unlock` module, kcrypt in
immucore), the splash draws a panel over the gradient and the logo: a title,
one dot per character, and "Wrong passphrase, try again" when the same `Id=`
comes back after an answer. The title is the question's `Message=` only when
it names no device (no `/`, no `luks`), and "Enter the disk passphrase"
otherwise. The VT stays in graphics mode, so no kernel text shows.

- **Keys**: tty1 in raw mode, so the kernel keymap applies. Enter answers,
  Backspace deletes, Esc and Ctrl-U clear, Ctrl-C cancels (the reply is `-`).
- **Protocol**: `ask.*` files in `/run/systemd/ask-password` through inotify,
  `NotAfter=` (hidden when it passes), `PID=` (ignored when the asker is
  gone), `Echo=`, `Silent=`, `Id=`, and the reply `+passphrase` or `-` on
  `Socket=`. Not root: `pkexec systemd-reply-password`, as the protocol says.
- **Only one agent asks.** The splash is an agent only with a framebuffer,
  the VT on stdin and the right to answer; then it writes its PID to
  `/run/isotope-ask/splash-agent`. The `51isotope-askpass` dracut module
  (`rootfs/usr/lib/dracut/modules.d/`) makes `kairos-splash.service`
  `Type=notify` (READY=1 comes after that decision) and gives
  `systemd-ask-password-console.service` an `ExecStartPre=` gate ordered after
  the splash. The gate waits while that PID lives. With no PID it stops the
  splash, which gives tty1 back to the console agent, so a machine with no
  framebuffer still gets the console prompt.
- **Keymap**: the installer puts `rd.vconsole.keymap=` on the command line
  (`install.grub_options.extra_cmdline`), because the initramfs's own
  `/etc/vconsole.conf` has no `KEYMAP`, and the drop-in orders the splash
  after `systemd-vconsole-setup.service`, which skips a VT in graphics mode.

`isotope.splash.agent=0` on the kernel command line, or `--no-agent`, leaves
the questions to the console agent. `--agent` makes the booted-system splash
an agent too. `make test` runs the protocol tests.

## Build and preview locally

    cd splash && make
    ./isotope-splash --render=frame.ppm --size=1920x1080 --at=2.5

`--at` is the animation time in seconds: the core lights at 0.25 s, the
shell at 0.55 s, the wordmark at 1 s, the side lifts at 1.55 s and the
information row comes in at 1.95 s. `--prompt=ask`, `--prompt=retry` or
`--prompt=checking` draws the
passphrase panel.

## Boot details (bootvine)

In the initramfs the splash shows "Press D for boot details" at the bottom of
the screen. D hands the screen to
[bootvine](https://codeberg.org/wvhulle/bootvine): a live tree of the boot's
systemd jobs, the units that failed with their reason and last log lines, and
a timeline of the slowest ones, on tty12. `isotope.bootvine` on the kernel
command line does the same from the start, with no animation; the GRUB menus
have an entry for it ("boot details" in the installed menu and on the live
ISO).

Kernel errors, such as a disk that fails a read or a GPU driver warning, reach
the console only on the boot details entries, which pass `loglevel=4`. The
other entries pass `loglevel=3`, but the console level is 4 again by the time
the real root starts; `isotope-console-level.service` (in `sysinit.target`)
applies the command line's last `loglevel=` again. An entry with no
`loglevel=` (recovery, the state reset) is left as the kernel has it.

- **Started by the splash only.** The Dockerfile `bootvine` stage installs
  `/usr/bin/bootvine` and `bootvine.service`, not enabled. The
  `52isotope-bootvine` dracut module copies both into the initramfs (bootvine's
  own module would enable it on every boot). The splash runs
  `systemctl start bootvine.service`, waits for it, and only then stops
  drawing, returns tty1 to text mode and exits. If the start fails, the
  splash carries on without the hint.
- **Only in the initramfs.** The booted-system splash lasts three seconds and
  the login screen takes tty1 right after it, so it does not offer D.
- **The rest of the boot.** bootvine survives switch-root by itself (`@` in
  its argv[0]) and follows the boot to the end. `/run/isotope-bootvine`, which
  the splash writes before the start, keeps the booted-system splash from
  drawing over it.
- **Passphrase.** bootvine is a password agent too and asks on its own
  console. The console agent's gate (`isotope-ask-gate.sh`) waits while
  `bootvine.service` is active, as it does for the splash, so only one of them
  asks.
- **Both renderers.** The framebuffer splash draws the hint under the
  boot lines; the text animation (no framebuffer in the initramfs, as on a
  BIOS VGA console) prints it on the second to last row. The text animation
  is never a password agent: the gate stops it before the console asks, so
  reading tty1 there takes no passphrase keys.
- **Keys.** D or d while no question is open. A question's panel takes every
  key, so D typed into a passphrase is a D. Escape sequences are skipped
  whole: the left arrow (`ESC [ D`) is not a D.

`--hint` with `--render` draws a frame with the hint, for previewing it.
