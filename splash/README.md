# hadron-desktop boot splash

Installed as `/usr/bin/kairos-splash`. kairos-init keeps an existing binary at
that path instead of linking its stock `kairos splash` there, and runs it in
both halves of the boot:

- **initramfs**: kairos-init's `50kairos-splash` dracut module copies it (and
  its libraries) into the initramfs. It runs with no arguments until SIGTERM at
  switch-root.
- **booted system**: `kairos-splash.service` runs it with `--duration=3s`
  before the login screen. A drop-in in
  `rootfs/usr/lib/systemd/system/kairos-splash.service.d/` orders it before
  `ly@tty1`.

`kairos.splash=0` on the kernel command line turns it off for one boot.

## Renderers

- **Framebuffer** (the normal case): draws into `/dev/fb0`, which every DRM
  driver exposes through fbdev emulation (simpledrm from the first moment of
  the initramfs, then virtio-gpu, i915, amdgpu...). The VT is switched to
  graphics mode so fbcon does not draw over it, and back on exit. The
  background is `tools/gen-grub-bg.py`'s gradient, so GRUB, the splash and the
  login screen read as one. When a native driver replaces simpledrm mid-boot,
  the splash notices the new geometry and reopens the framebuffer.
- **Text**: the VGA-16 console animation, for a VT with no framebuffer.
- **No terminal**: prints `HADRON <version>` and exits.

The version comes from `/etc/kairos/branding/splash/version`, which the
Dockerfile writes before kairos-init builds the initramfs, so both halves show
the same release.

Text is drawn with Terminus 8x16 (`font.h`, generated by
`tools/gen-splash-font.py`), the same face as the console.

## Disk passphrase

In the initramfs the splash is also a systemd password agent
(`agent.c`, systemd's `docs/PASSWORD_AGENTS.md`). When something asks for a
password with `systemd-ask-password` (the `hadron-unlock` module, kcrypt in
immucore), the splash draws a panel over the gradient and the logo: a title,
one dot per character, and "Wrong passphrase, try again" when the same `Id=`
comes back after an answer. The title is the question's `Message=` only when
it names no device (no `/`, no `luks`), and "Enter the disk passphrase"
otherwise. The VT stays in graphics mode, so no kernel text shows.

- **Keys**: tty1 in raw mode, so the kernel keymap applies. Enter answers,
  Backspace deletes, Esc and Ctrl-U clear, Ctrl-C cancels (the reply is `-`).
- **Protocol**: `ask.*` files in `/run/systemd/ask-password` through inotify,
  `NotAfter=` (hidden when it passes), `PID=` (ignored when the asker is
  gone), `Echo=`, `Silent=`, `Id=`, and the reply `+passphrase` or `-` on
  `Socket=`. Not root: `pkexec systemd-reply-password`, as the protocol says.
- **Only one agent asks.** The splash is an agent only with a framebuffer,
  the VT on stdin and the right to answer; then it writes its PID to
  `/run/hadron-ask/splash-agent`. The `51hadron-askpass` dracut module
  (`rootfs/usr/lib/dracut/modules.d/`) makes `kairos-splash.service`
  `Type=notify` (READY=1 comes after that decision) and gives
  `systemd-ask-password-console.service` an `ExecStartPre=` gate ordered after
  the splash. The gate waits while that PID lives. With no PID it stops the
  splash, which gives tty1 back to the console agent, so a machine with no
  framebuffer still gets the console prompt.
- **Keymap**: the installer puts `rd.vconsole.keymap=` on the command line
  (`install.grub_options.extra_cmdline`), because the initramfs's own
  `/etc/vconsole.conf` has no `KEYMAP`, and the drop-in orders the splash
  after `systemd-vconsole-setup.service`, which skips a VT in graphics mode.

`hadron.splash.agent=0` on the kernel command line, or `--no-agent`, leaves
the questions to the console agent. `--agent` makes the booted-system splash
an agent too. `make test` runs the protocol tests.

## Build and preview locally

    cd splash && make
    ./hadron-splash --render=frame.ppm --size=1920x1080 --at=2.5

`--at` is the animation time in seconds: under 1.1 s the logo is still
glitching in. `--prompt=ask`, `--prompt=retry` or `--prompt=checking` draws
the passphrase panel.
